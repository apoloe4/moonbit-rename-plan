# 设计与复杂度

## 为什么是库

`cmd/demo` 直接导入公共 MoonBit 模块并在 Wasm-GC 上运行。CLI 和网页仅是调用者；删除 web/ 和 cli.mjs 不影响 MoonBit 的规划、规则、恢复和日志测试。

## 规划算法

1. 预检完整快照与映射，建立策略下的规范键集合；拒绝重复来源、重复目标及静止条目占用。
2. 按来源名 UTF-16 字典序排序任务。来源与目标完全相同的任务记为 skipped。
3. 优先执行目标当前空闲的任务。任务完成会释放其旧来源，使链上前驱有机会执行。
4. 若没有任务可执行，剩余子图存在循环。选择排序中第一个未完成任务，停放至唯一临时名，然后重新扫描。
5. 已暂存任务最终移入其目标。临时名称依次编号，且避开最初快照、全部目标和历史临时名。

预检使用映射表；扫描式规划最坏 O(M²)，图解释的反向边扫描也是 O(M²)，空间 O(N+M)。有意限制 N/M≤1000，而不是声称海量目录性能。对合法一对一映射，一个长度 k 的循环需要 k+1 次操作；大小写自环需要两次，链不使用临时名。

## 恢复与证据

恢复从 initial 开始逐步回放，在每个边界比较完整规范化排序后的精确名称及身份。无匹配则输出最近边界的差异，仅用于解释，不能据此自动生成补救操作。多匹配则报告 ambiguous。普通恢复不会仅按条目数、最终文件是否存在或最近相似快照猜测。

日志核对先以状态机验证 intent/result 的次序和绑定。未结束意图只允许“该步骤前”或“该步骤后”两种状态；这可处理文件系统操作已成功但完成记录尚未写入的情况。这个模型依赖外部单次改名原子性，不等于证明断电安全。

恢复逐步比较快照，最坏约 O(S·N log N)，不缓存所有快照。`verify_boundaries` 会回放每个前缀及其后续/逆向步骤，规模受 200 步上限控制。

## 规则展开

按精确名称排序，先做后缀筛选，然后拆分最后一个扩展名；前导点不视为扩展名分隔符。字面替换仅作用于主体；prefix、编号、主体、suffix、扩展名依次组合，最后应用 ASCII 大小写转换。无正则、无模板执行、无 shell 插值。生成结果不能绕过规划预检。

## 身份

核心仅依赖 opaque identity。CLI 使用文件内容 SHA-256，不能区分同内容的不同物理文件；这是显式歧义，而不是偷偷按名称猜测。精确对象身份（例如持久稳定 file ID）可由集成方提供，跨平台稳定性由集成方负责。

## 输入约束

单层名称及常见跨平台禁用字符检查不是完整 OS 校验。支持 exact 与 ASCII-fold 两种显式等价策略，不将 ASCII-fold 宣称为 Windows 模拟器。不做 Unicode 正规化、不跟随子目录、不生成 shell 执行脚本。
